Chapter 03

Trees and Traversals

Tree terminology, representations, and the four ways to walk a binary tree.

From a line to a hierarchy

A linked list is a line: each node has one successor. That linearity is exactly what makes search \(O(n)\) — to find the last element you must walk past every earlier one. A tree relaxes the constraint to allow more than one successor, and with two successors per node the number of elements reachable in \(h\) steps grows like \(2^h\). That is where the speed comes from, and chapter 4 exploits it.

Definition — tree

A tree is either (a) a single node, or (b) a node called the root connected to zero or more disjoint subtrees. Equivalently, in graph terms, a tree is a connected acyclic graph. The two definitions are equivalent, and the course uses both — chapter 7 revisits the second.

Exam trap

Height is measured in edges, not nodes, in this course. A single node has height 0 and depth 0. Mixing the two conventions is the most common source of off-by-one errors in AVL questions.

Counting facts worth memorising

  • A binary tree of height \(h\) has at most \(2^{h+1} - 1\) nodes.
  • A binary tree with \(n\) nodes has height at least \(\lfloor \log_2 n \rfloor\).
  • A full binary tree with \(L\) leaves has exactly \(2L - 1\) nodes.
  • The number of nodes at depth \(d\) in a perfect tree is \(2^d\).
Worked example — why height is logarithmic

A binary tree of height \(h\) has at most \(1 + 2 + 4 + \cdots + 2^h = 2^{h+1} - 1\) nodes. If it holds \(n\) nodes then \(n \le 2^{h+1} - 1\), so \(h \ge \log_2(n+1) - 1 = \Omega(\log n)\).

This is a lower bound on height for a given \(n\). The upper bound is unbounded — a chain of \(n\) nodes has height \(n-1\). Chapter 5 fixes that.

Representing a binary tree

RepresentationHowCost
Array (heap style)Node at index \(i\) has children \(2i+1\) and \(2i+2\), parent \(\lfloor (i-1)/2 \rfloor\)\(O(1)\) navigation, but wastes space on sparse trees
LinkedEach node holds a value and two pointersExactly \(O(n)\) space, \(O(1)\) child access

The array form only makes sense for complete trees — those filled level by level from the left — because otherwise the indices leave gaps. Chapter 6 uses it for heaps, where completeness is part of the invariant.

The four traversals

A traversal is a systematic order in which to visit every node exactly once. The three depth-first orders differ only in when the node itself is visited relative to its subtrees.

TraversalOrderTypical use
Preordernode, left, rightCopy a tree; produce a prefix expression
Inorderleft, node, rightSorted output from a BST — the reason BSTs are useful
Postorderleft, right, nodeDelete a tree; evaluate a postfix expression
Level orderby depth, left to right (uses a queue)Breadth-first over a tree

The traversals in pseudocode

The three depth-first orders differ only in where the visit line sits. Writing them this way makes the symmetry obvious, and it is what the exam expects if you are asked to "give the algorithm" rather than the output.

PseudocodeDEPTH-FIRST TRAVERSALS
PREORDER(x):
    if x == nil: return
    visit(x)                 # node first
    PREORDER(x.left)
    PREORDER(x.right)

INORDER(x):
    if x == nil: return
    INORDER(x.left)
    visit(x)                 # node in the middle
    INORDER(x.right)

POSTORDER(x):
    if x == nil: return
    POSTORDER(x.left)
    POSTORDER(x.right)
    visit(x)                 # node last
PseudocodeLEVEL ORDER
LEVEL-ORDER(root):
    if root == nil: return
    Q = empty queue
    ENQUEUE(Q, root)
    while Q not empty:
        x = DEQUEUE(Q)
        visit(x)
        if x.left  != nil: ENQUEUE(Q, x.left)     # left before right
        if x.right != nil: ENQUEUE(Q, x.right)
Iterative form

Any depth-first traversal can be rewritten with an explicit stack, which removes the recursion-depth limit. For preorder the stack holds nodes to visit; for inorder the standard form walks left pushing onto the stack, then pops and moves right:

INORDER-ITERATIVE(root):
    stack = empty
    x = root
    while stack not empty or x != nil:
        while x != nil:
            PUSH(stack, x); x = x.left
        x = POP(stack)
        visit(x)
        x = x.right
Worked example — all four orders on one tree

Root 4, with left child 2 (children 1 and 3) and right child 6 (children 5 and 7).

OrderSequence
Preorder4 2 1 3 6 5 7
Inorder1 2 3 4 5 6 7
Postorder1 3 2 5 7 6 4
Level order4 2 6 1 3 5 7

Notice that inorder is sorted. That is not a coincidence — this tree happens to be a BST, and chapter 4 makes the connection precise.

C implementation

Ctree.c
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int value;
    struct Node *left, *right;
} Node;

Node *node_new(int v) {
    Node *n = malloc(sizeof *n);
    if (!n) return NULL;
    n->value = v; n->left = n->right = NULL;
    return n;
}

/* height in edges; a leaf has height 0, an empty tree -1 */
int height(const Node *n) {
    if (!n) return -1;
    int l = height(n->left), r = height(n->right);
    return 1 + (l > r ? l : r);
}

int count(const Node *n) {
    return n ? 1 + count(n->left) + count(n->right) : 0;
}

void preorder(const Node *n)  { if (!n) return; printf("%d ", n->value); preorder(n->left);  preorder(n->right); }
void inorder(const Node *n)   { if (!n) return; inorder(n->left);  printf("%d ", n->value);   inorder(n->right);  }
void postorder(const Node *n) { if (!n) return; postorder(n->left); postorder(n->right); printf("%d ", n->value); }

/* postorder is the safe way to free: children before parent */
void tree_free(Node *n) {
    if (!n) return;
    tree_free(n->left);
    tree_free(n->right);
    free(n);
}

int main(void) {
    /*        4
             / \
            2   6
           / \ / \
          1  3 5  7   */
    Node *root = node_new(4);
    root->left = node_new(2);  root->right = node_new(6);
    root->left->left = node_new(1);  root->left->right = node_new(3);
    root->right->left = node_new(5); root->right->right = node_new(7);

    printf("height %d, nodes %d\n", height(root), count(root));
    printf("pre   "); preorder(root);  printf("\n");
    printf("in    "); inorder(root);   printf("\n");
    printf("post  "); postorder(root); printf("\n");
    tree_free(root);
    return 0;
}
/* output:
   height 2, nodes 7
   pre   4 2 1 3 6 5 7
   in    1 2 3 4 5 6 7
   post  1 3 2 5 7 6 4        */

Python implementation

Pythontree.py
from collections import deque


class Node:
    __slots__ = ("value", "left", "right")
    def __init__(self, value, left=None, right=None):
        self.value = value
        self.left = left
        self.right = right


def height(node):
    """Height in edges; a leaf is 0, an empty tree is -1."""
    if node is None:
        return -1
    return 1 + max(height(node.left), height(node.right))


def preorder(node, out):
    if node is None:
        return
    out.append(node.value)
    preorder(node.left, out)
    preorder(node.right, out)


def inorder(node, out):
    if node is None:
        return
    inorder(node.left, out)
    out.append(node.value)
    inorder(node.right, out)


def postorder(node, out):
    if node is None:
        return
    postorder(node.left, out)
    postorder(node.right, out)
    out.append(node.value)


def level_order(root):
    """Breadth-first: a queue of nodes, not a recursion."""
    if root is None:
        return []
    out, q = [], deque([root])
    while q:
        node = q.popleft()
        out.append(node.value)
        if node.left:
            q.append(node.left)
        if node.right:
            q.append(node.right)
    return out


if __name__ == "__main__":
    root = Node(4,
                Node(2, Node(1), Node(3)),
                Node(6, Node(5), Node(7)))
    print("height:", height(root))
    for name, fn in (("pre", preorder), ("in", inorder), ("post", postorder)):
        out = []
        fn(root, out)
        print(name, out)
    print("level", level_order(root))
Recursion depth

All three depth-first traversals are \(O(n)\) time but \(O(h)\) stack space. On a degenerate tree — a chain — that is \(O(n)\) frames. Python's default recursion limit is 1000, so a chain of 2000 nodes raises RecursionError. C has no such limit but will overflow the stack around a few hundred thousand frames. Level order avoids this entirely by using an explicit queue.

Complexity summary

OperationTimeSpace
Any depth-first traversal\(O(n)\)\(O(h)\) stack
Level-order traversal\(O(n)\)\(O(w)\) where w is the widest level
Height / count\(O(n)\)\(O(h)\) stack
Free the tree\(O(n)\)\(O(h)\) stack

Check your understanding

A binary tree has 31 nodes and is perfect (every level completely filled). What is its height in edges?
A perfect tree of height h has 2^(h+1) − 1 nodes. Setting 2^(h+1) − 1 = 31 gives 2^(h+1) = 32, so h + 1 = 5 and h = 4. Five is the number of levels, which is the off-by-one trap.
Which traversal should you use to free every node of a tree safely?
You must free a node's children before the node itself, or you lose the pointers to them and leak the subtree. Postorder visits both subtrees before the node, which is exactly the order required.
