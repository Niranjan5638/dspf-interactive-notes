Chapter 01

Measuring Cost: Complexity and Asymptotic Notation

Why we compare algorithms by growth, and how to read O, Omega, Theta, o and omega.

Why we need a way to measure cost

Two programs solve the same problem. On my laptop, the first finishes in 0.4 seconds and the second in 0.7. Which one should you use?

That question cannot be answered by the numbers alone, because the numbers depend on the machine, the compiler, the input size and what else was running. Change the input from a thousand items to a million and the ranking may reverse entirely. What we need is a measure that ignores the accidents of hardware and captures the thing that actually matters: how the work grows as the input grows.

The intuition

Imagine two runners. One is faster over 100 metres. The other tires more slowly. For a sprint you pick the first; for a marathon the second. Complexity analysis is the study of "how fast do you tire", and it is the only thing that predicts behaviour at large scale.

Concretely: an algorithm that takes \(n^2\) operations on input size \(n\) will, at \(n = 10{,}000\), need a hundred million operations. At \(n = 100{,}000\) it needs ten billion. An algorithm that takes \(n \log n\) needs about 133,000 and 1.66 million respectively. No amount of constant-factor tuning closes a gap that widens like that.

Counting operations

We start by counting how many times the innermost statement of a piece of code executes, as a function of the input size \(n\).

Ccount1.c
int sum = 0;                        /* 1 operation        */
for (int i = 0; i < n; i++)         /* n+1 comparisons    */
    sum += a[i];                    /* n additions        */

The loop body runs exactly \(n\) times. The comparison runs \(n+1\) times, because it is tested once more to discover the loop is finished. So the total is about \(2n + 2\) operations. We will call that \(O(n)\).

Now nest a second loop:

Ccount2.c
int count = 0;
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        count++;                    /* runs n * n times   */

The inner statement runs \(n^2\) times, so the cost is \(O(n^2)\). But notice the third pattern, which is the one students misjudge:

Ccount3.c
int count = 0;
for (int i = 0; i < n; i++)
    for (int j = 0; j < i; j++)     /* j stops at i, not n */
        count++;

The inner loop runs \(0\) times when \(i = 0\), \(1\) time when \(i = 1\), and so on up to \(n-1\). The total is

\[ 0 + 1 + 2 + \cdots + (n-1) = \frac{n(n-1)}{2} = \frac{n^2}{2} - \frac{n}{2} \]

which is still \(O(n^2)\). The factor of one half is irrelevant once we take the limit — that is exactly what asymptotic notation formalises.

Common mistake

"The inner loop depends on i, so it is \(O(n)\) total." No. The sum of an arithmetic series in \(n\) terms is quadratic. Triangular loops are \(O(n^2)\).

The five notations

Asymptotic notation is a way of describing a function's growth while ignoring constants and lower-order terms. There are five symbols, and the exam expects you to know all of them and the differences between them.

NotationRead asFormal definitionMeaning in words
\(O(f(n))\)big-Oh\(\exists c > 0, n_0 : \forall n \ge n_0,\; T(n) \le c\,f(n)\)Grows no faster than f — an upper bound
\(\Omega(f(n))\)big-Omega\(\exists c > 0, n_0 : \forall n \ge n_0,\; T(n) \ge c\,f(n)\)Grows at least as fast as f — a lower bound
\(\Theta(f(n))\)big-ThetaBoth of the above holdGrows exactly like f — a tight bound
\(o(f(n))\)little-oh\(\forall c > 0, \exists n_0 : \forall n \ge n_0,\; T(n) < c\,f(n)\)Grows strictly slower than f
\(\omega(f(n))\)little-omega\(\forall c > 0, \exists n_0 : \forall n \ge n_0,\; T(n) > c\,f(n)\)Grows strictly faster than f

The difference between \(O\) and \(o\) is the same as the difference between \(\le\) and \(<\). \(2n^2 = O(n^2)\) is true, and \(2n^2 = o(n^3)\) is true, but \(2n^2 = o(n^2)\) is false.

Worked example — proving a bound from the definition

Show that \(3n^2 + 5n + 2 = O(n^2)\).

We must exhibit constants \(c\) and \(n_0\) such that \(3n^2 + 5n + 2 \le c\,n^2\) for all \(n \ge n_0\).

For \(n \ge 1\): \(5n \le 5n^2\) and \(2 \le 2n^2\). So

\[ 3n^2 + 5n + 2 \le 3n^2 + 5n^2 + 2n^2 = 10n^2 \]

Take \(c = 10\) and \(n_0 = 1\). The definition is satisfied, so the claim holds. ∎

Note that any larger \(c\) would also work. The definition only requires some constants to exist, which is why we can always throw away lower-order terms.

The growth hierarchy

From slowest-growing to fastest-growing:

\[ 1 \;<\; \log\log n \;<\; \log n \;<\; \sqrt{n} \;<\; n \;<\; n\log n \;<\; n^2 \;<\; n^3 \;<\; 2^n \;<\; n! \]

The single most useful fact on this line: \(\log n\) grows so slowly that doubling \(n\) adds only one to it. Binary search on a billion items needs about 30 comparisons. That is why "logarithmic" is effectively "free".

Growth-rate explorer

How to analyse a piece of code

  1. Find the dominant operation. Usually the innermost statement of the deepest loop.
  2. Express its execution count as a function of \(n\). Sum the loop bounds.
  3. Drop constants and lower-order terms. \(3n^2 + 5n + 2\) becomes \(n^2\).
  4. State the result. \(O(n^2)\).
PatternCostWhy
Single loop over n\(O(n)\)Body runs n times
Nested loop, both to n\(O(n^2)\)n × n
Triangular nested loop\(O(n^2)\)Sum of 1..n is n(n+1)/2
Loop that halves the input\(O(\log n)\)Number of halvings to reach 1
Three nested loops to n\(O(n^3)\)n × n × n
Loop over all subsets\(O(2^n)\)2 choices per element
Loop over all permutations\(O(n!)\)n choices, then n−1, …
Worked example — a loop that does not look logarithmic
Chalving.c
int i = n, steps = 0;
while (i > 1) {
    i = i / 2;
    steps++;
}

After \(k\) iterations, \(i = n / 2^k\). The loop stops when \(n/2^k \le 1\), that is \(k \ge \log_2 n\). So the cost is \(O(\log n)\).

The base of the logarithm does not matter asymptotically: \(\log_2 n = \log_{10} n / \log_{10} 2\), and the constant \(1/\log_{10}2\) is absorbed by the \(O\).

Recurrences

Recursive algorithms need a different technique: write the cost of the problem in terms of the cost of its subproblems, then solve.

RecurrenceSolutionWhere it appears
\(T(n) = T(n/2) + 1\)\(\Theta(\log n)\)Binary search, halving loop
\(T(n) = T(n-1) + 1\)\(\Theta(n)\)Linear recursion
\(T(n) = 2T(n/2) + n\)\(\Theta(n \log n)\)Merge sort, divide and conquer
\(T(n) = 2T(n-1) + 1\)\(\Theta(2^n)\)Naive subset recursion
Worked example — solving \(T(n) = 2T(n/2) + n\) by unrolling

Substitute repeatedly:

\[ \begin{aligned} T(n) &= 2T(n/2) + n \\ &= 2\bigl(2T(n/4) + n/2\bigr) + n = 4T(n/4) + 2n \\ &= 4\bigl(2T(n/8) + n/4\bigr) + 2n = 8T(n/8) + 3n \end{aligned} \]

After \(k\) steps: \(T(n) = 2^k T(n/2^k) + kn\). The recursion stops when \(n/2^k = 1\), that is \(k = \log_2 n\). Then

\[ T(n) = n\,T(1) + n\log_2 n = \Theta(n\log n) \]

Amortised analysis: the doubling array

Here is a question that looks like a trick and is not. A dynamic array starts with capacity 1. Each push appends an element; when the array is full, it allocates twice the capacity and copies everything over. What is the cost of one push?

The worst case is terrible: when the array is full, a single push costs \(O(n)\). But that cannot be the whole story, because it only happens occasionally. Amortised analysis averages over a sequence of operations and asks for the cost per operation in that sequence.

Worked example — the doubling argument

Consider \(n\) pushes. The copies happen when the array grows from 1 to 2, 2 to 4, 4 to 8, and so on. The total copying work is

\[ 1 + 2 + 4 + 8 + \cdots + n < 2n \]

because the sum of a geometric series is less than twice its largest term. Add the \(n\) pushes themselves and the total work over the whole sequence is at most \(3n\). Dividing by \(n\) operations gives \(O(1)\) amortised per push.

Now change one thing — grow by a constant \(k\) instead of doubling — and the analysis collapses. Copies then happen every \(k\) pushes, and the total copying work becomes \(k + 2k + 3k + \cdots \approx n^2/2k\), which is \(O(n^2)\) overall, or \(O(n)\) amortised per push. This is exactly why your lecture spends a whole topic on the exponential growth strategy.

Exam trap

Amortised \(O(1)\) does not mean every individual push is \(O(1)\). It means the average over a long sequence is \(O(1)\). A single push can still cost \(O(n)\). If a question asks for the worst case of one push, the answer is \(O(n)\); if it asks for the amortised cost, the answer is \(O(1)\).

Space complexity

Time is not the only resource. Space complexity counts the extra memory an algorithm needs beyond its input — the auxiliary space.

  • An in-place algorithm uses \(O(1)\) auxiliary space. Heapsort is in place; merge sort is not.
  • Recursion uses stack space proportional to depth. A recursive DFS on a graph of \(V\) vertices uses \(O(V)\) stack in the worst case.
  • Building an adjacency list for a graph uses \(O(V + E)\); an adjacency matrix uses \(O(V^2)\).

C and Python implementations

The same counting exercise in both languages. Note that Python hides the loop overhead inside the interpreter, so the constants differ wildly — but the growth rate does not.

Ccomplexity_demo.c
#include <stdio.h>
#include <stdlib.h>

/* O(n) - one pass over the array */
long sum_array(const int *a, int n) {
    long total = 0;
    for (int i = 0; i < n; i++)      /* n iterations */
        total += a[i];
    return total;
}

/* O(n^2) - every pair, i < j only */
long count_pairs(const int *a, int n) {
    long pairs = 0;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)   /* triangular loop */
            if (a[i] + a[j] == 0) pairs++;
    return pairs;
}

/* O(log n) - halve until 1 */
int halvings(int n) {
    int steps = 0;
    while (n > 1) { n /= 2; steps++; }
    return steps;
}

int main(void) {
    int n = 8;
    int a[] = {1, -1, 2, -2, 3, -3, 4, -4};
    printf("sum        = %ld\n", sum_array(a, n));
    printf("zero pairs = %ld\n", count_pairs(a, n));
    printf("halvings   = %d\n", halvings(n));
    return 0;
}
/* output:
   sum        = 0
   zero pairs = 4
   halvings   = 3            */
Pythoncomplexity_demo.py
def sum_list(a):
    """O(n) - one pass."""
    total = 0
    for x in a:
        total += x
    return total


def count_pairs(a):
    """O(n^2) - triangular double loop."""
    pairs = 0
    n = len(a)
    for i in range(n):
        for j in range(i + 1, n):
            if a[i] + a[j] == 0:
                pairs += 1
    return pairs


def halvings(n):
    """O(log n) - halve until 1."""
    steps = 0
    while n > 1:
        n //= 2
        steps += 1
    return steps


if __name__ == "__main__":
    a = [1, -1, 2, -2, 3, -3, 4, -4]
    print("sum        =", sum_list(a))
    print("zero pairs =", count_pairs(a))
    print("halvings   =", halvings(8))

What differs between the two

  • Speed of the constant. The C loop is perhaps 50 times faster per iteration. That changes the constant factor, never the growth rate.
  • Overflow. In C, long overflows silently on large sums. Python integers grow arbitrarily, so sum_list is correct for any size — at the cost of memory.
  • Iteration cost. Python's for x in a is implemented in C internally and is fast; a manual index loop is slower. In C, the index loop is the idiomatic form.

Common mistakes

  1. Writing \(O(2n)\) or \(O(n + 5)\). Constants are absorbed: these are \(O(n)\).
  2. Keeping lower-order terms. \(O(n^2 + n)\) is \(O(n^2)\).
  3. Assuming nested loops are always \(O(n^2)\). Only if both bounds are \(n\). A loop over the bits of a number is \(O(\log n)\) per number.
  4. Confusing best, average and worst case. Linear search is \(O(1)\) best, \(O(n)\) worst. State which you mean.
  5. Treating \(O\) as "equals". \(f(n) = O(g)\) is really \(f(n) \in O(g)\). The equality is a convention.

Check your understanding

What is the time complexity of this loop?
for (i = 1; i < n; i *= 2) sum++;
The counter doubles each iteration: 1, 2, 4, 8, … It exceeds n after ⌈log₂ n⌉ steps, so the loop body runs O(log n) times. Multiplying the counter instead of incrementing it is what makes it logarithmic.
Is it true that \(5n + 3 = \Theta(n)\)?
Upper bound: \(5n + 3 \le 8n\) for \(n \ge 1\). Lower bound: \(5n + 3 \ge 5n\). Both hold, so Θ(n). A function is Θ(g) exactly when it is both O(g) and Ω(g).
An array that doubles when full is pushed to n times. What is the amortised cost per push?
The copies total 1 + 2 + 4 + … + n < 2n, so over n pushes the work is O(n) and the average is O(1). The worst case of a single push is still O(n) — that is the distinction amortised analysis draws.
