Chapter 02

Stacks, Queues and Linked Lists

LIFO and FIFO containers, how they are built on arrays and pointers, and why the circular buffer exists.

Two ways to decide who goes next

Every container answers one question: when something asks for the next item, which item should it get? A stack answers "the most recent one". A queue answers "the oldest one". That is the entire difference, and it turns out to be the difference between depth-first and breadth-first traversal later in the course.

Why these two and not something else

LIFO matches every situation where you must finish what you started before returning: function calls, undo history, bracket matching, backtracking. FIFO matches every situation where fairness or arrival order matters: printer queues, request buffering, and level-by-level exploration of a graph.

Abstract data type versus implementation

An abstract data type specifies what the operations do, not how they are done. This separation is the point of the chapter: the same stack ADT can be an array or a linked list, and the choice is a complexity decision, not a correctness one.

Definition — stack ADT

A collection supporting push(x) (add to the top), pop() (remove and return the top), top() (read the top without removing), isEmpty(), and size(). The defining property is that the item removed is always the one most recently added — last in, first out.

Definition — queue ADT

A collection supporting enqueue(x) (add at the rear), dequeue() (remove and return the front), front(), isEmpty(), and size(). The defining property is that the item removed is always the one least recently added — first in, first out.

Implementations and their costs

StackQueue
Array implementation\(O(1)\) push and pop at the endNaive array gives \(O(n)\) dequeue; use a circular buffer for \(O(1)\)
Linked implementation\(O(1)\) push and pop at the head\(O(1)\) enqueue at tail, dequeue at head

Why the circular queue exists

In a naive array queue you enqueue at the back and dequeue from the front. The front index marches forward while the back stays put, so the queue walks off the end of the array even though most of it is empty. Shifting every element left after each dequeue costs \(O(n)\) and defeats the purpose.

The fix is to make the indices wrap: rear = (rear + 1) % capacity. Now the array is treated as a ring, and both operations are \(O(1)\). The cost is that you must track the size explicitly to distinguish "full" from "empty" — both states have front == rear.

Stack and queue

Linked lists

An array stores elements contiguously, so access by index is \(O(1)\) but insertion in the middle is \(O(n)\) because everything after it must shift. A linked list stores each element in its own node together with a pointer to the next, so insertion is \(O(1)\) once you hold the position — but reaching that position costs \(O(n)\).

VariantStructureWhat it buys
Singly linkedEach node points to the next\(O(1)\) insert and delete at the head; \(O(n)\) search

Array or linked list?

Answer by naming the operation, not the structure. "\(O(1)\) random access" favours the array. "\(O(1)\) insert in the middle" favours the list. But remember the hidden costs: an array is cache-friendly and a linked list is not, so on real hardware the array often wins even where the asymptotics favour the list.

C implementation

A stack on an array with the doubling strategy from chapter 1, and a queue as a circular buffer.

Cstack.c
#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int *data;
    int size;       /* number of elements stored */
    int capacity;   /* allocated slots           */
} Stack;

Stack *stack_new(void) {
    Stack *s = malloc(sizeof *s);
    if (!s) return NULL;
    s->capacity = 2;
    s->size = 0;
    s->data = malloc(s->capacity * sizeof(int));
    if (!s->data) { free(s); return NULL; }
    return s;
}

/* O(1) amortised: doubles only when full */
void push(Stack *s, int v) {
    if (s->size == s->capacity) {
        int *bigger = realloc(s->data, s->capacity * 2 * sizeof(int));
        if (!bigger) return;              /* allocation failed */
        s->data = bigger;
        s->capacity *= 2;
    }
    s->data[s->size++] = v;
}

/* O(1) */
int pop(Stack *s, int *out) {
    if (s->size == 0) return 0;           /* underflow */
    *out = s->data[--s->size];
    return 1;
}

void stack_free(Stack *s) {
    free(s->data);   /* free the buffer ... */
    free(s);         /* ... then the struct  */
}

int main(void) {
    Stack *s = stack_new();
    for (int i = 1; i <= 3; i++) push(s, i * 10);
    int v;
    while (pop(s, &v)) printf("%d ", v);   /* prints 30 20 10 */
    printf("\n");
    stack_free(s);
    return 0;
}
Cqueue.c
#include <stdio.h>
#define CAP 8

typedef struct {
    int data[CAP];
    int front;   /* index of the oldest element */
    int rear;    /* index where the next one goes */
    int count;   /* needed to tell full from empty */
} Queue;

void q_init(Queue *q) { q->front = q->rear = q->count = 0; }

int q_enqueue(Queue *q, int v) {
    if (q->count == CAP) return 0;        /* full */
    q->data[q->rear] = v;
    q->rear = (q->rear + 1) % CAP;        /* wrap around */
    q->count++;
    return 1;
}

int q_dequeue(Queue *q, int *out) {
    if (q->count == 0) return 0;          /* empty */
    *out = q->data[q->front];
    q->front = (q->front + 1) % CAP;      /* wrap around */
    q->count--;
    return 1;
}

int main(void) {
    Queue q; q_init(&q);
    for (int i = 1; i <= 3; i++) q_enqueue(&q, i * 10);
    int v;
    while (q_dequeue(&q, &v)) printf("%d ", v);   /* prints 10 20 30 */
    printf("\n");
    return 0;
}

Python implementation

Python lists already behave as stacks: append and pop are both \(O(1)\) amortised at the right-hand end, using exactly the doubling strategy above. For a queue, a list is the wrong tool — list.pop(0) is \(O(n)\) because every remaining element shifts. Use collections.deque, which is a doubly linked block structure with \(O(1)\) at both ends.

Pythoncontainers.py
from collections import deque

# A stack: list is already a stack at the right-hand end.
stack = []
stack.append(10)      # push  -> O(1) amortised
stack.append(20)
stack.append(30)
print(stack.pop())    # 30, LIFO -> O(1)

# A queue: deque, never list.pop(0) which is O(n).
q = deque()
q.append(10)          # enqueue -> O(1)
q.append(20)
q.append(30)
print(q.popleft())    # 10, FIFO -> O(1)

# A linked list, built by hand to show the pointers explicitly.
class Node:
    __slots__ = ("value", "next")
    def __init__(self, value, next=None):
        self.value = value
        self.next = next


def reverse(head):
    """Reverse a singly linked list in place. O(n) time, O(1) space."""
    prev = None
    cur = head
    while cur:
        nxt = cur.next      # 1. remember the rest
        cur.next = prev     # 2. flip this pointer
        prev = cur          # 3. advance prev
        cur = nxt           # 4. advance cur
    return prev             # prev is the new head


head = Node(1, Node(2, Node(3)))
head = reverse(head)
while head:
    print(head.value, end=" ")   # 3 2 1
    head = head.next

Memory, the honest difference

In C you own the memory. malloc returns a block, realloc may move it, and free returns it. Forget to free and you leak; free twice and you corrupt the heap; keep a pointer after freeing and you have a dangling reference.

In Python you own nothing. Objects are reference-counted and collected when unreachable. A list of integers stores pointers to int objects, not raw integers, so it uses far more memory than a C array of the same length — typically 8 bytes per pointer plus 28 bytes per small integer, against 4 bytes per int in C.

Common mistakes

  1. Popping an empty stack. Always check. In C this reads garbage; in Python it raises IndexError.
  2. Using list.pop(0) as a queue. It is \(O(n)\) and quietly turns a linear algorithm into a quadratic one.
  3. Losing the head pointer while traversing a linked list, leaking the rest of the list.
  4. Freeing the struct before the buffer. Free the inner allocation first.
  5. Confusing full and empty in a circular queue without a size counter.

Check your understanding

A queue is implemented on an array of capacity 8 using front and rear indices that wrap modulo 8. After 5 enqueues and 5 dequeues, what are front and rear?
Both indices advanced 5 times and wrap modulo 8, so both sit at 5. The queue is empty because count is zero — which is exactly why the counter is needed: front == rear alone cannot distinguish empty from full.
Which operation is not \(O(1)\) on a singly linked list when you hold a pointer to the node?
To delete a node from a singly linked list you must update its predecessor's next pointer, and finding the predecessor requires walking from the head — \(O(n)\). A doubly linked list fixes this in \(O(1)\), which is precisely why it exists.
