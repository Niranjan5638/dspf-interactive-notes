Shortest Paths

Dijkstra, Bellman-Ford and Floyd-Warshall — outside the examinable syllabus.

Supplementary — outside the examinable syllabus

This chapter is not covered by the ten lecture sessions for this course. Your graph material is lectures 13 (terminology), 14 (BFS), 15 (DFS) and 16 (MST); there is no shortest-path lecture. It is included because it is the natural next question after BFS and because Dijkstra is referenced repeatedly in chapters 8 and 10 as a contrast. Revise it after the examinable chapters, not before.

The problem

Chapter 8 established that BFS finds the path with the fewest edges. Once edges carry weights, fewest edges and cheapest path are different questions, and BFS answers the wrong one.

Definition — single-source shortest paths

Given a weighted graph \(G = (V, E)\) with edge weights \(w(u,v)\) and a source \(s\), find for every vertex \(v\) the minimum total weight \(\delta(s,v)\) of any path from \(s\) to \(v\), and a path achieving it.

Three algorithms cover the space, and the choice between them is decided by two questions: do you need one source or all pairs, and can any edge weight be negative?

AlgorithmSolvesNegative weightsTime
BFSSingle source, unweightedn/a\(O(V+E)\)
DijkstraSingle sourceNo\(O((V+E)\log V)\)
Bellman–FordSingle sourceYes, and detects negative cycles\(O(VE)\)
Floyd–WarshallAll pairsYes, and detects negative cycles\(O(V^3)\)

The one idea all three share: relaxation

Every algorithm below maintains an array dist[] holding the best known distance to each vertex, initialised to infinity except dist[s] = 0. The core operation is relaxation: if going through \(u\) reaches \(v\) more cheaply than the current best, update it.

RELAX(u, v, w): if dist[u] + w(u,v) < dist[v]: dist[v] = dist[u] + w(u,v) parent[v] = u

The three algorithms differ only in how many times and in what order they relax edges. Dijkstra relaxes each edge once, from vertices taken in increasing order of distance. Bellman–Ford relaxes every edge \(V-1\) times, which is enough for any shortest path since a simple path has at most \(V-1\) edges. Floyd–Warshall relaxes over every possible intermediate vertex.

Dijkstra's algorithm

The idea

Grow a set \(S\) of vertices whose final distance is known. Repeatedly take the vertex \(u \notin S\) with the smallest tentative distance, add it to \(S\), and relax all its outgoing edges. Because the smallest tentative distance is never wrong, each vertex is finalised once.

PseudocodeDijkstra
DIJKSTRA(G, w, s):
    for each v: dist[v] = infinity; parent[v] = nil
    dist[s] = 0
    S = empty                       # finalised vertices
    PQ = all vertices keyed by dist

    while PQ not empty:
        u = extract-min(PQ)         # smallest tentative distance
        S = S + {u}
        for each neighbour v of u:
            RELAX(u, v, w)          # may call decrease-key on PQ

Complexity: \(O((V+E)\log V)\) with a binary heap, \(O(V^2)\) with an array scan (better for dense graphs), \(O(E + V\log V)\) with a Fibonacci heap.

Why non-negative weights are required

The failure, and why it happens

Dijkstra assumes that once a vertex is extracted with the smallest tentative distance, no cheaper route to it can appear later. That is true only if all weights are non-negative: a later route would have to pass through a vertex with an even smaller distance, which has already been extracted, and then add a non-negative amount.

Counterexample. Vertices A, B, C. Edges A–B weight 2, A–C weight 5, C–B weight −4. Dijkstra extracts A, sets dist[B] = 2 and dist[C] = 5, then extracts B with distance 2 and finalises it. But the true distance to B is A→C→B = 5 + (−4) = 1. The algorithm reports 2. A negative edge broke the assumption.

Bellman–Ford

The idea

Relax every edge, \(V-1\) times over. A shortest path uses at most \(V-1\) edges, so after \(k\) full passes every shortest path of at most \(k\) edges is correct. After \(V-1\) passes everything reachable is correct.

The extra power is the negative cycle test: run one more pass, and if any edge can still be relaxed, a negative cycle exists — a cycle whose total weight is negative, around which you could loop forever to make the distance arbitrarily small. No well-defined shortest path exists in that case.

PseudocodeBellman-Ford
BELLMAN-FORD(G, w, s):
    for each v: dist[v] = infinity; parent[v] = nil
    dist[s] = 0

    repeat V-1 times:
        for each edge (u, v) in E:
            RELAX(u, v, w)

    # V-th pass: any relaxation means a negative cycle
    for each edge (u, v) in E:
        if dist[u] + w(u,v) < dist[v]:
            return "negative cycle reachable from s"

    return dist

Complexity: \(O(VE)\) time, \(O(V)\) space. On a sparse graph that is \(O(V^2)\), which is why Dijkstra is preferred whenever weights are non-negative.

Worked example — negative edges but no negative cycle

Edges: A–B 6, A–C 7, B–C 8, B–D 5, B–E −4, C–D −3, C–E 9, D–F 2, E–F 7, E–D 7. Source A.

Pass 1: B=6, C=7. Then from B: D=11, E=2. From C: D=min(11, 4)=4, E=min(2,16)=2. From D: F=6. From E: F=min(6,9)=6, D=min(4,9)=4.

Pass 2: no edge improves anything — because the negative edge B→E was processed before C→D, distances settled in one pass. In general you need up to \(V-1\) passes; this graph happens to converge early, which is why implementations often track whether a pass changed anything and stop.

The final distances use the negative edge: \(\delta(A,E) = 6 + (-4) = 2\), which Dijkstra would have computed correctly here only by luck of ordering.

Negative cycle vs negative edge

A negative edge is fine for Bellman–Ford; it just needs more passes. A negative cycle makes the problem ill-posed: the distance to any vertex reachable from the cycle is \(-\infty\). The V-th pass is the test that distinguishes them, and an exam question will usually ask you to state which one you have.

Floyd–Warshall

The idea

All-pairs shortest paths by dynamic programming. Number the vertices \(1 \ldots V\) and let \(d^{(k)}(i,j)\) be the cheapest path from \(i\) to \(j\) using only vertices from \(\{1,\ldots,k\}\) as intermediates. Either the path avoids \(k\), or it goes through \(k\):

\[ d^{(k)}(i,j) = \min\Bigl(d^{(k-1)}(i,j),\; d^{(k-1)}(i,k) + d^{(k-1)}(k,j)\Bigr) \]

That is the whole algorithm: three nested loops, one line in the middle.

PseudocodeFloyd-Warshall
FLOYD-WARSHALL(W):                 # W[i][j] = edge weight, or infinity
    D = copy of W
    for i in 1..V: D[i][i] = 0

    for k in 1..V:                  # k must be the OUTER loop
        for i in 1..V:
            for j in 1..V:
                if D[i][k] + D[k][j] < D[i][j]:
                    D[i][j] = D[i][k] + D[k][j]

    return D

Complexity: \(O(V^3)\) time, \(O(V^2)\) space. Negative edges are fine; a negative value on the diagonal \(D[i][i]\) afterwards indicates a negative cycle.

The one implementation detail that matters

k must be the outermost loop. Swapping it inward gives a different, incorrect algorithm — it would only consider paths whose intermediate vertices appear in a fixed order. This is the single most common Floyd–Warshall error, and it is worth being able to explain why: the recurrence is defined over the set of permitted intermediates, so that set must be built up one vertex at a time, outside the pair loops.

Worked example — a 4-vertex graph

Adjacency matrix with infinity (∞) for absent edges:

InitialD⁰
      1    2    3    4
 1 [  0    3    6    ∞ ]
 2 [  ∞    0    ∞    1 ]
 3 [  ∞   -2    0    ∞ ]
 4 [  2    ∞    ∞    0 ]

Note the negative edge 3→2 of weight −2. After \(k = 1\): no improvement through vertex 1 except 4→2 = 2+3 = 5. After \(k = 2\): 3→2→4 gives 3→4 = −2 + 1 = −1, and 1→2→4 gives 3 + 1 = 4. After \(k = 3\): 2→3→2 would be −2, but 2→3 is ∞ so no change; 4→1→... unchanged. Final distances include \(d(3,4) = -1\) and \(d(4,2) = 5\).

No negative value appears on the diagonal, so there is no negative cycle.

C implementation

Cshortest_paths.c
#include <stdio.h>
#include <limits.h>

#define V 6
#define INF INT_MAX

/* ---------- Dijkstra on an adjacency matrix, O(V^2) ---------- */
void dijkstra(int w[V][V], int src) {
    int dist[V], done[V];
    for (int i = 0; i < V; i++) { dist[i] = INF; done[i] = 0; }
    dist[src] = 0;

    for (int step = 0; step < V; step++) {
        int u = -1, best = INF;
        for (int i = 0; i < V; i++)
            if (!done[i] && dist[i] < best) { best = dist[i]; u = i; }
        if (u == -1) break;                 /* remaining unreachable */
        done[u] = 1;
        for (int v = 0; v < V; v++)
            if (w[u][v] != INF && dist[u] != INF &&
                dist[u] + w[u][v] < dist[v])
                dist[v] = dist[u] + w[u][v];
    }
    printf("Dijkstra from %d:\n", src);
    for (int i = 0; i < V; i++)
        printf("  %d: %s%d\n", i, dist[i] == INF ? "unreachable " : "", dist[i]);
}

/* ---------- Bellman-Ford on an edge list, O(VE) ---------- */
typedef struct { int u, v, w; } Edge;

int bellman_ford(Edge e[], int m, int src, int dist[]) {
    for (int i = 0; i < V; i++) dist[i] = INF;
    dist[src] = 0;

    for (int pass = 0; pass < V - 1; pass++)
        for (int i = 0; i < m; i++)
            if (dist[e[i].u] != INF &&
                dist[e[i].u] + e[i].w < dist[e[i].v])
                dist[e[i].v] = dist[e[i].u] + e[i].w;

    for (int i = 0; i < m; i++)             /* V-th pass: detection */
        if (dist[e[i].u] != INF &&
            dist[e[i].u] + e[i].w < dist[e[i].v])
            return 0;                       /* negative cycle */
    return 1;
}

/* ---------- Floyd-Warshall, O(V^3) ---------- */
void floyd_warshall(int d[V][V]) {
    for (int k = 0; k < V; k++)             /* k OUTERMOST */
        for (int i = 0; i < V; i++)
            for (int j = 0; j < V; j++)
                if (d[i][k] != INF && d[k][j] != INF &&
                    d[i][k] + d[k][j] < d[i][j])
                    d[i][j] = d[i][k] + d[k][j];
}

int main(void) {
    int w[V][V];
    for (int i = 0; i < V; i++)
        for (int j = 0; j < V; j++)
            w[i][j] = (i == j) ? 0 : INF;
    /* A=0 B=1 C=2 D=3 E=4 F=5 */
    w[0][1]=4; w[0][2]=2; w[1][2]=1; w[1][3]=5;
    w[2][3]=8; w[2][4]=10; w[3][4]=2; w[3][5]=6; w[4][5]=3;

    dijkstra(w, 0);          /* A:0 B:3 C:2 D:8 E:10 F:13 */

    Edge e[] = {{0,1,6},{0,2,7},{1,2,8},{1,3,5},{1,4,-4},
                {2,3,-3},{2,4,9},{3,5,2},{4,5,7},{4,3,7}};
    int dist[V];
    if (bellman_ford(e, 10, 0, dist)) {
        printf("Bellman-Ford from 0:\n");
        for (int i = 0; i < V; i++) printf("  %d: %d\n", i, dist[i]);
    } else {
        printf("negative cycle detected\n");
    }

    floyd_warshall(w);
    printf("All pairs (row 0): ");
    for (int j = 0; j < V; j++) printf("%d ", w[0][j]);
    printf("\n");
    return 0;
}
Pythonshortest_paths.py
import heapq
from math import inf


def dijkstra(adj, source):
    """Single source, non-negative weights. O((V+E) log V)."""
    dist = {source: 0}
    parent = {source: None}
    pq = [(0, source)]
    done = set()

    while pq:
        d, u = heapq.heappop(pq)
        if u in done:
            continue
        done.add(u)
        for v, w in adj.get(u, ()):
            if w < 0:
                raise ValueError("Dijkstra requires non-negative weights")
            nd = d + w
            if nd < dist.get(v, inf):
                dist[v] = nd
                parent[v] = u
                heapq.heappush(pq, (nd, v))
    return dist, parent


def bellman_ford(n, edges, source):
    """Handles negative edges; detects negative cycles. O(VE)."""
    dist = {i: inf for i in range(n)}
    dist[source] = 0

    for _ in range(n - 1):
        changed = False
        for u, v, w in edges:
            if dist[u] != inf and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                changed = True
        if not changed:                 # converged early
            break

    for u, v, w in edges:               # extra pass = detection
        if dist[u] != inf and dist[u] + w < dist[v]:
            return None, True           # negative cycle
    return dist, False


def floyd_warshall(n, edges):
    """All pairs. O(V^3) time, O(V^2) space."""
    d = [[inf] * n for _ in range(n)]
    for i in range(n):
        d[i][i] = 0
    for u, v, w in edges:
        d[u][v] = min(d[u][v], w)

    for k in range(n):                  # k OUTERMOST
        for i in range(n):
            for j in range(n):
                if d[i][k] + d[k][j] < d[i][j]:
                    d[i][j] = d[i][k] + d[k][j]

    negative_cycle = any(d[i][i] < 0 for i in range(n))
    return d, negative_cycle

Choosing between them

SituationUseWhy
Unweighted graph, one sourceBFS\(O(V+E)\), and weights are all 1 so edges = cost
Non-negative weights, one source, sparseDijkstra with a heap\(O((V+E)\log V)\)
Non-negative weights, one source, denseDijkstra with an array\(O(V^2)\), simpler and faster in practice
Any negative edgesBellman–FordDijkstra is incorrect; Bellman–Ford also detects negative cycles
All pairs, dense graphFloyd–Warshall\(O(V^3)\) regardless of \(E\); also simple to code
All pairs, sparse graphDijkstra or Bellman–Ford from each vertex\(O(V(V+E)\log V)\) beats \(O(V^3)\) when \(E \ll V^2\)
Distances that keep arriving (routing)Bellman–Ford styleDistributed; each node only needs its neighbours
MST versus shortest path — the distinction that trips people up

In the graph of chapter 10 (A–B 4, A–C 2, B–C 1, B–D 5, C–D 8, C–E 10, D–E 2, D–F 6, E–F 3), the MST has total weight 13 and contains edges {BC, AC, DE, EF, BD}.

Dijkstra from A gives \(\delta(A,F) = 13\) via A→C→B→D→E→F, using edges AC, CB, BD, DE, EF — which happens to be a subset of the MST here. That is a coincidence, not a theorem. Add an edge A–F of weight 20 and the shortest path to F becomes 20 while the MST still routes through the whole graph. The MST minimises total edge weight across the tree; shortest paths minimise the distance from one source to one target. An MST can contain a long detour to avoid a single expensive edge.

Common mistakes

  1. Using Dijkstra with negative weights. It silently returns wrong answers rather than failing, which is worse. The counterexample is in the warning box above.
  2. Putting k inside the pair loops in Floyd–Warshall. The result is a different algorithm.
  3. Running only one Bellman–Ford pass. You need \(V-1\), because a shortest path may use up to \(V-1\) edges.
  4. Confusing an MST with a shortest-path tree. They optimise different objectives.
  5. Forgetting the negative-cycle pass. Without it Bellman–Ford returns meaningless distances around the cycle.
  6. Comparing INF + w in C. INT_MAX + 4 overflows to a negative number and the comparison succeeds. Always guard with dist[u] != INF.

Check your understanding

A graph has a negative edge but no negative cycle. Which algorithms give correct shortest paths?
A negative edge breaks Dijkstra's assumption that the smallest tentative distance is final, so it can return a wrong answer. Bellman–Ford and Floyd–Warshall make no such assumption and handle negative edges fine. Shortest paths are only undefined when there is a negative cycle.
In Floyd–Warshall, why must k be the outermost loop?
d(k)(i,j) is defined as the best path using only vertices 1..k as intermediates. Layer k must be fully computed for every pair before layer k+1 begins, so k drives the outer loop. Swapping it inside gives a different, incorrect algorithm.
Bellman–Ford has finished its V−1 passes and one more edge can still be relaxed. What does that mean?
After V−1 passes every shortest path — which uses at most V−1 edges — is correct. If something can still be improved, the improvement must come from a cycle of negative total weight, around which you could loop indefinitely. V−1 passes is already the maximum needed, so more passes would not help.
