Connecting everything as cheaply as possible

You have a set of cities and a cost for every possible road between them. You must connect all the cities, using only some of the roads, at minimum total cost. That is the minimum spanning tree problem, and it is the last structure in the course because it needs both the graph representation of chapter 7 and the traversal ideas of chapters 8 and 9.

Definition — minimum spanning tree

For a connected weighted undirected graph \(G = (V, E)\), a spanning tree is a subgraph that is a tree and contains all \(V\) vertices. A minimum spanning tree (MST) is a spanning tree of minimum total edge weight.

A spanning tree on \(V\) vertices always has exactly \(V - 1\) edges. If a graph has \(m\) distinct edge weights, its MST is unique; with ties, several MSTs of equal weight may exist.

The cut property — why both algorithms work

Definition — cut and the cut property

A cut partitions the vertices into two non-empty sets. An edge crosses the cut if its endpoints are on opposite sides. The cut property states: for any cut, the lightest edge crossing it belongs to some MST.

Proof of the cut property

Let \(e\) be the lightest edge crossing cut \((S, V-S)\), and let \(T\) be an MST that does not contain \(e\). Adding \(e\) to \(T\) creates a cycle, and that cycle must cross the cut an even number of times, so it contains another crossing edge \(f\). By the choice of \(e\), \(w(e) \le w(f)\).

Then \(T - f + e\) is still a spanning tree (removing a cycle edge keeps it connected and acyclic) with weight no greater than \(T\). Since \(T\) was minimum, so is the new tree, and it contains \(e\). ∎

Both algorithms below are repeated applications of that fact. Kruskal takes the globally lightest edge that does not create a cycle; Prim grows a tree by repeatedly taking the lightest edge leaving it.

Kruskal's algorithm

Sort all edges by weight. Scan in increasing order, adding each edge that does not create a cycle, until \(V-1\) edges are accepted. Cycle testing uses union-find (disjoint sets), which gives near-constant amortised time per operation.

PseudocodeKruskal
KRUSKAL(G):
    result = empty
    for each vertex v: MAKE-SET(v)
    sort edges by weight ascending
    for each edge (u, v) in sorted order:
        if FIND(u) != FIND(v):        # different components
            result.add((u, v))
            UNION(u, v)
            if |result| == |V| - 1: break
    return result

Complexity: \(O(E \log E)\) for the sort, which dominates. Union-find with path compression and union by rank is \(O(E \alpha(V))\), effectively linear.

Prim's algorithm

Start from any vertex. Repeatedly add the lightest edge connecting the current tree to a vertex outside it. A priority queue of crossing edges makes each step \(O(\log V)\).

PseudocodePrim
PRIM(G, start):
    for each vertex v: key[v] = infinity; inTree[v] = false
    key[start] = 0; parent[start] = nil
    PQ = all vertices keyed by key
    while PQ not empty:
        u = extract-min(PQ)
        inTree[u] = true
        for each neighbour v of u with weight w:
            if not inTree[v] and w < key[v]:
                key[v] = w; parent[v] = u
                decrease-key(PQ, v, w)

Complexity: \(O(E \log V)\) with a binary heap, \(O(E + V \log V)\) with a Fibonacci heap.

C implementation

Ckruskal.c
#include <stdio.h>
#include <stdlib.h>

#define MAXV 100
#define MAXE 1000

typedef struct { int u, v, w; } Edge;

static int cmp(const void *a, const void *b) {
    return ((const Edge *)a)->w - ((const Edge *)b)->w;
}

/* ---- union-find with path compression + union by rank ---- */
int parent[MAXV], rank_[MAXV];

void uf_init(int n) {
    for (int i = 0; i < n; i++) { parent[i] = i; rank_[i] = 0; }
}

int find(int x) {
    while (parent[x] != x) {
        parent[x] = parent[parent[x]];   /* path halving */
        x = parent[x];
    }
    return x;
}

int unite(int a, int b) {
    a = find(a); b = find(b);
    if (a == b) return 0;                /* already together: would cycle */
    if (rank_[a] < rank_[b]) { int t = a; a = b; b = t; }
    parent[b] = a;
    if (rank_[a] == rank_[b]) rank_[a]++;
    return 1;
}

int main(void) {
    int n = 6;
    Edge e[] = {{0,1,4},{0,2,2},{1,2,1},{1,3,5},{2,3,8},{2,4,10},{3,4,2},{3,5,6},{4,5,3}};
    int m = sizeof e / sizeof e[0];

    qsort(e, m, sizeof(Edge), cmp);
    uf_init(n);

    int total = 0, used = 0;
    for (int i = 0; i < m && used < n - 1; i++) {
        if (unite(e[i].u, e[i].v)) {
            printf("add %d-%d (weight %d)\n", e[i].u, e[i].v, e[i].w);
            total += e[i].w;
            used++;
        } else {
            printf("skip %d-%d (weight %d) - would form a cycle\n", e[i].u, e[i].v, e[i].w);
        }
    }
    printf("MST weight = %d over %d edges\n", total, used);
    return 0;
}
/* output ends with:
   MST weight = 13 over 5 edges   */
Pythonmst.py
import heapq


class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]   # path halving
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        return True


def kruskal(n, edges):
    """edges: list of (weight, u, v). Returns (total, chosen)."""
    uf = UnionFind(n)
    total, chosen = 0, []
    for w, u, v in sorted(edges):
        if uf.union(u, v):
            chosen.append((u, v, w))
            total += w
            if len(chosen) == n - 1:
                break
    return total, chosen


def prim(n, adj, start=0):
    """adj: {u: [(v, w), ...]}. Returns (total, chosen)."""
    in_tree = [False] * n
    total, chosen = 0, []
    pq = [(0, start, None)]
    while pq:
        w, u, p = heapq.heappop(pq)
        if in_tree[u]:
            continue
        in_tree[u] = True
        total += w
        if p is not None:
            chosen.append((p, u, w))
        for v, wt in adj.get(u, ()):
            if not in_tree[v]:
                heapq.heappush(pq, (wt, v, u))
    return total, chosen


if __name__ == "__main__":
    edges = [(4,0,1),(2,0,2),(1,1,2),(5,1,3),(8,2,3),(10,2,4),(2,3,4),(6,3,5),(3,4,5)]
    print(kruskal(6, edges))       # (13, [...])

    for w, u, v in edges:
        adj.setdefault(u, []).append((v, w))
        adj.setdefault(v, []).append((u, w))
    print(prim(6, adj))            # (13, [...])

Common mistakes

  1. Accepting a cheap edge that closes a cycle. In Kruskal the cycle test is the algorithm; skipping it produces a spanning subgraph, not a tree.
  2. Stopping early. You need exactly \(V-1\) edges; fewer means the graph is disconnected.
  3. Assuming the MST is unique. With tied weights several distinct trees can share the minimum total.
  4. Using Prim on a disconnected graph and reporting a spanning tree. It returns a spanning tree of one component only.
  5. Confusing MST with shortest paths. The MST minimises total edge weight; Dijkstra minimises the distance from one source. The MST can contain a long detour to avoid an expensive edge.

Check your understanding

A connected graph has 9 vertices. How many edges are in any spanning tree of it?
Every spanning tree on V vertices has exactly V − 1 edges, whatever the weights. That is a consequence of being connected and acyclic.
Kruskal's algorithm rejects the edge A–B of weight 4. Why?
Kruskal's only rejection criterion is the cycle test, performed by union-find. At that point A and B are both already connected through C (via A–C and C–B), so find(A) == find(B) and the edge is skipped — even though it is cheap.
