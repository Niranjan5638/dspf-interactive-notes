Adding order to a tree

Chapter 3's tree lets you visit every node, but finding one still requires visiting everything. A binary search tree adds a single rule that turns the tree into an ordered map with logarithmic search — provided the tree stays balanced, which is chapter 5's problem.

Definition — BST property

For every node \(x\): every key in the left subtree of \(x\) is less than \(x\)'s key, and every key in the right subtree is greater. Duplicates are either forbidden or handled by a fixed convention (keep a count, or always go right).

Three consequences follow immediately, and they are the ones to state in an exam: an inorder traversal yields the keys in sorted order; the minimum is the leftmost node; and the maximum is the rightmost.

The operations

OperationHowCost
SearchCompare at the root; go left if smaller, right if larger\(O(h)\)
InsertSearch to a null child, attach the new key there\(O(h)\)
Minimum / maximumFollow left / right pointers to the end\(O(h)\)
SuccessorRight subtree's minimum, or climb until you come up from a left child\(O(h)\)
DeleteThree cases — see below\(O(h)\)

Everything is \(O(h)\), not \(O(\log n)\). The two are the same only when the tree is balanced, and that distinction is the whole point of the chapter.

The operations in pseudocode

Search and insert are single descents. Deletion is the only one with real structure, and it is written here using a helper, TRANSPLANT, that replaces one subtree with another — which keeps the three cases from turning into nine.

PseudocodeSEARCH, MINIMUM, SUCCESSOR
TREE-SEARCH(x, k):                # O(h), iterative
    while x != nil and k != x.key:
        if k < x.key: x = x.left
        else:         x = x.right
    return x                      # nil if absent

TREE-MINIMUM(x):                  # O(h) - leftmost node
    while x.left != nil: x = x.left
    return x

TREE-MAXIMUM(x):                  # O(h) - rightmost node
    while x.right != nil: x = x.right
    return x

TREE-SUCCESSOR(x):                # O(h)
    if x.right != nil:
        return TREE-MINIMUM(x.right)   # leftmost of right subtree
    y = x.parent
    while y != nil and x == y.right:   # climb while we are a right child
        x = y
        y = y.parent
    return y                      # nil if x was the maximum
PseudocodeINSERT AND DELETE
TREE-INSERT(T, z):                # O(h)
    y = nil                       # y will be z's parent
    x = T.root
    while x != nil:
        y = x
        if z.key < x.key: x = x.left
        else:             x = x.right
    z.parent = y
    if y == nil:          T.root = z      # tree was empty
    else if z.key < y.key: y.left  = z
    else:                  y.right = z

TRANSPLANT(T, u, v):              # replace subtree rooted at u with v
    if u.parent == nil:        T.root = v
    else if u == u.parent.left:  u.parent.left  = v
    else:                        u.parent.right = v
    if v != nil: v.parent = u.parent

TREE-DELETE(T, z):                # O(h)
    if z.left == nil:
        TRANSPLANT(T, z, z.right)          # case 1 or 2
    else if z.right == nil:
        TRANSPLANT(T, z, z.left)           # case 2
    else:                                   # case 3: two children
        y = TREE-MINIMUM(z.right)           # inorder successor
        if y.parent != z:
            TRANSPLANT(T, y, y.right)       # lift y's right child
            y.right = z.right
            y.right.parent = y
        TRANSPLANT(T, z, y)                 # y takes z's place
        y.left = z.left
        y.left.parent = y
Why TRANSPLANT earns its own procedure

Every deletion case is "cut out a subtree and splice another into its place". Writing that once means each case is a single line, and it also handles the awkward sub-case where the successor is not z's direct child. Without it the third case needs its own four pointer updates and is the usual place students lose marks.

Deletion, the three cases

  1. Leaf. Remove it. The parent's pointer becomes null.
  2. One child. Splice the child into the node's place. The parent now points at the grandchild.
  3. Two children. Replace the node's key with its inorder successor — the minimum of the right subtree — then delete that successor. By construction the successor has no left child, so it falls into case 1 or 2.
Worked example — deleting a two-child node

Tree: 50 with left 30 (children 20, 40) and right 70 (children 60, 80). Delete 50.

The inorder successor of 50 is the minimum of its right subtree: 60. Copy 60 into the root, then delete 60 from the right subtree. Node 60 was a leaf, so this is case 1. Result: root 60, left 30 (20, 40), right 70 (—, 80).

The tree is still a valid BST, and inorder still reads 20 30 40 60 70 80.

The successor, and why it works

To find the successor of a key \(k\): if \(k\)'s right subtree is non-empty, the successor is its minimum. Otherwise the successor is the lowest ancestor whose left subtree contains \(k\) — found by climbing while you are the right child.

Worked example — both branches

In the tree above (after deletion: root 60, left 30 with children 20 and 40, right 70 with child 80):

  • Successor of 30: right subtree exists, its minimum is 40. Answer 40.
  • Successor of 40: no right subtree, so climb — 40 is a right child of 30, continue; 30 is a left child of 60, stop. Answer 60.
  • Successor of 80: no right subtree; 80 is a right child of 70, 70 is a right child of 60, 60 has no parent. Answer: none, 80 is the maximum.

The degenerate case

Insert 10, 20, 30, 40, 50 in that order. Every new key is larger than everything before it, so it always goes to the right. The result is a chain of height 4 with five nodes: search is now \(O(n)\), and the tree has degenerated into a linked list.

The same five keys inserted in the order 30, 20, 40, 10, 50 give a balanced tree of height 2. The shape depends entirely on insertion order, which is why the average case (\(O(\log n)\) for random order) and the worst case (\(O(n)\)) are so far apart.

Why this motivates AVL

Every BST operation costs \(O(h)\). The structure is only useful when \(h = O(\log n)\), and nothing in the BST definition guarantees that. Chapter 5 adds an invariant that does — at the cost of some rebalancing work on insert and delete.

C implementation

Cbst.c
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int key;
    struct Node *left, *right;
} Node;

Node *node_new(int k) {
    Node *n = malloc(sizeof *n);
    if (!n) return NULL;
    n->key = k; n->left = n->right = NULL;
    return n;
}

/* O(h) */
Node *bst_search(Node *t, int k) {
    while (t && t->key != k)
        t = (k < t->key) ? t->left : t->right;
    return t;
}

/* O(h): walk down to a null child and attach */
Node *bst_insert(Node *t, int k) {
    if (!t) return node_new(k);
    if (k < t->key)      t->left  = bst_insert(t->left,  k);
    else if (k > t->key) t->right = bst_insert(t->right, k);
    return t;                       /* duplicates ignored */
}

Node *bst_min(Node *t) {
    if (!t) return NULL;
    while (t->left) t = t->left;
    return t;
}

/* successor: right subtree's min, else lowest ancestor we came up from the left */
Node *bst_successor(Node *root, int k) {
    Node *succ = NULL, *t = root;
    while (t && t->key != k) {
        if (k < t->key) { succ = t; t = t->left; }
        else            { t = t->right; }
    }
    if (!t) return NULL;
    if (t->right) return bst_min(t->right);
    return succ;
}

/* O(h) - the three cases */
Node *bst_delete(Node *t, int k) {
    if (!t) return NULL;
    if (k < t->key)      { t->left  = bst_delete(t->left,  k); return t; }
    if (k > t->key)      { t->right = bst_delete(t->right, k); return t; }

    if (!t->left)  { Node *r = t->right; free(t); return r; }   /* case 1/2 */
    if (!t->right) { Node *l = t->left;  free(t); return l; }   /* case 2   */
    Node *s = bst_min(t->right);                                /* case 3   */
    t->key = s->key;
    t->right = bst_delete(t->right, s->key);
    return t;
}

void inorder(const Node *t) {
    if (!t) return;
    inorder(t->left); printf("%d ", t->key); inorder(t->right);
}

int main(void) {
    Node *root = NULL;
    int keys[] = {50, 30, 70, 20, 40, 60, 80};
    for (int i = 0; i < 7; i++) root = bst_insert(root, keys[i]);
    inorder(root); printf("\n");                 /* 20 30 40 50 60 70 80 */
    printf("succ(40) = %d\n", bst_successor(root, 40)->key);   /* 50 */
    root = bst_delete(root, 50);
    inorder(root); printf("\n");                 /* 20 30 40 60 70 80 */
    return 0;
}

Python implementation

Pythonbst.py
class Node:
    __slots__ = ("key", "left", "right")
    def __init__(self, key):
        self.key = key
        self.left = self.right = None


class BST:
    def __init__(self):
        self.root = None

    def insert(self, key):
        """O(h). Iterative, so no recursion limit."""
        if self.root is None:
            self.root = Node(key)
            return
        cur = self.root
        while True:
            if key < cur.key:
                if cur.left is None:
                    cur.left = Node(key)
                    return
                cur = cur.left
            elif key > cur.key:
                if cur.right is None:
                    cur.right = Node(key)
                    return
                cur = cur.right
            else:
                return                       # duplicate

    def search(self, key):
        cur = self.root
        while cur and cur.key != key:
            cur = cur.left if key < cur.key else cur.right
        return cur

    def inorder(self):
        out, stack, cur = [], [], self.root
        while stack or cur:                  # explicit stack, O(h) space
            while cur:
                stack.append(cur)
                cur = cur.left
            cur = stack.pop()
            out.append(cur.key)
            cur = cur.right
        return out

    def delete(self, key):
        def _del(node, k):
            if node is None:
                return None
            if k < node.key:
                node.left = _del(node.left, k)
            elif k > node.key:
                node.right = _del(node.right, k)
            else:
                if node.left is None:
                    return node.right
                if node.right is None:
                    return node.left
                succ = node.right
                while succ.left:
                    succ = succ.left
                node.key = succ.key
                node.right = _del(node.right, succ.key)
            return node
        self.root = _del(self.root, key)


if __name__ == "__main__":
    t = BST()
    for k in (50, 30, 70, 20, 40, 60, 80):
        t.insert(k)
    print(t.inorder())      # [20, 30, 40, 50, 60, 70, 80]
    t.delete(50)
    print(t.inorder())      # [20, 30, 40, 60, 70, 80]

Build a BST

Common mistakes

  1. Deleting a two-child node by promoting the left child. That breaks the ordering. The successor (or predecessor) is the only safe replacement.
  2. Assuming search is \(O(\log n)\) always. It is \(O(h)\), and \(h\) can be \(n-1\).
  3. Forgetting to update the parent's pointer when deleting the root.
  4. Comparing only with the parent during search instead of walking from the root.
  5. Allowing duplicates silently. Choose a convention and state it.

Check your understanding

Keys 1, 2, 3, 4, 5 are inserted into an empty BST in that order. What is the height of the resulting tree?
Each key is larger than all previous ones, so each becomes a right child of the previous — a chain of 5 nodes. Height in edges is 5 − 1 = 4. This is the degenerate case; search is now O(n).
What is the inorder successor of a node with a non-empty right subtree?
Everything in the right subtree is greater than the node, and the smallest of those is the next key in sorted order. Following left pointers to the end of the right subtree finds it in O(h).
