Fixing the degenerate case

Chapter 4 ended with a problem: a BST built from sorted keys is a linked list, and every operation degrades to \(O(n)\). The fix is to add a second invariant that forces the tree to stay bushy, and to repair it locally after every modification.

Definition — AVL tree

A binary search tree in which, for every internal node, the heights of its two subtrees differ by at most 1. The balance factor of a node is

\[ \text{bf}(x) = \text{height}(\text{left}(x)) - \text{height}(\text{right}(x)) \]

and must be −1, 0 or +1 at every node.

AVL trees are named after Adelson-Velskii and Landis, who published them in 1962 — the first self-balancing search tree.

The height bound, and why it matters

The claim is that an AVL tree with \(n\) nodes has height \(O(\log n)\). The proof defines \(n(h)\) as the minimum number of internal nodes in an AVL tree of height \(h\), and asks how sparse an AVL tree can be.

To minimise nodes while keeping the balance condition, make one subtree as short as legally allowed: height \(h-1\) on one side and \(h-2\) on the other. Then

\[ n(h) = n(h-1) + n(h-2) + 1, \qquad n(1) = 1,\; n(2) = 2 \]

This is the Fibonacci recurrence. Its solution grows exponentially in \(h\) — the values are 1, 2, 4, 7, 12, 20, 33, 54, … — so inverting it gives \(h = O(\log n)\). Concretely, an AVL tree of height 20 holds at least 17,711 nodes.

Worked example — counting the minimum

Height 1: one node. Height 2: a root plus one child = 2 nodes. Height 3: root, one subtree of height 2 (2 nodes) and one of height 1 (1 node) = 1 + 2 + 1 = 4. Height 4: 1 + 4 + 2 = 7. Height 5: 1 + 7 + 4 = 12. Height 6: 1 + 12 + 7 = 20.

Compare a perfect tree, which would hold \(2^{h+1}-1\): at height 5 that is 63 nodes against the AVL minimum of 12. The AVL tree is allowed to be much sparser, but never exponentially sparser.

The four rotation cases

After an insertion, walk up from the new node to the first unbalanced node \(z\). Let \(y\) be \(z\)'s taller child and \(x\) be \(y\)'s taller child. There are four shapes, named by the path \(z \to y \to x\).

CaseShapeFixExample insertion order
LLz, y, x all lean leftSingle right rotation about z30, 20, 10
RRz, y, x all lean rightSingle left rotation about z10, 20, 30
LRx is the right child of a left childLeft rotate about y, then right rotate about z30, 10, 20
RLx is the left child of a right childRight rotate about y, then left rotate about z10, 30, 20
Worked example — LL

Insert 30, then 20 (left child), then 10 (left child of 20). Node 30 has balance factor \(+2\).

Beforeright rotation about 30
      30  (bf +2)                 20
     /                          /    \
   20          --------->     10      30
   /
 10

The inorder sequence 10, 20, 30 is preserved, and every balance factor is now 0. Height falls from 3 to 2.

Worked example — LR

Insert 30, then 10, then 20. Node 30 has balance factor \(+2\), and the path is left (to 10) then right (to 20). A single rotation cannot fix it: rotating right about 30 would put 10 on top with 20 still to its right, leaving 10 unbalanced.

Step 1: left-rotate about 10. The subtree 10→20 becomes 20 with left child 10. Now 30's left child is 20, whose left child is 10 — an LL shape.

Step 2: right-rotate about 30. Node 20 becomes the subtree root with children 10 and 30.

The memory aid that never fails

In every case, the middle value of the three becomes the new subtree root, and the other two become its children in key order. LL has values 10, 20, 30 → 20 on top. RL has 10, 20, 30 → 20 on top. The rotations are just the mechanism for performing that rearrangement while preserving the BST property.

Insertion versus deletion

InsertionDeletion
Rotations neededAt most one (single or double)Possibly O(log n), cascading to the root
WhyA rotation restores the subtree's height to what it was before the insert, so nothing above is disturbedA deletion lowers a subtree's height, and the rotation that fixes one ancestor may itself shorten that ancestor, propagating upward
Exam trap

"One rotation is enough" is true for insertion and false for deletion. Students routinely write it for both. State which operation you mean.

C implementation

Cavl.c
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int key, height;
    struct Node *left, *right;
} Node;

int h(const Node *n)  { return n ? n->height : -1; }
int max(int a, int b) { return a > b ? a : b; }
int bf(const Node *n) { return n ? h(n->left) - h(n->right) : 0; }

void fix_height(Node *n) { n->height = 1 + max(h(n->left), h(n->right)); }

Node *rotate_right(Node *z) {          /*       z            y
                                          / \          / \
                                         y   c   -->  a   z
                                        / \              / \
                                       a   b            b   c   */
    Node *y = z->left;
    z->left = y->right;
    y->right = z;
    fix_height(z); fix_height(y);
    return y;
}

Node *rotate_left(Node *z) {
    Node *y = z->right;
    z->right = y->left;
    y->left = z;
    fix_height(z); fix_height(y);
    return y;
}

Node *rebalance(Node *z) {
    fix_height(z);
    if (bf(z) > 1) {                       /* left-heavy */
        if (bf(z->left) < 0) z->left = rotate_left(z->left);   /* LR */
        return rotate_right(z);                                 /* LL */
    }
    if (bf(z) < -1) {                      /* right-heavy */
        if (bf(z->right) > 0) z->right = rotate_right(z->right); /* RL */
        return rotate_left(z);                                   /* RR */
    }
    return z;
}

Node *avl_insert(Node *t, int k) {
    if (!t) {
        Node *n = malloc(sizeof *n);
        n->key = k; n->height = 0; n->left = n->right = NULL;
        return n;
    }
    if (k < t->key)      t->left  = avl_insert(t->left,  k);
    else if (k > t->key) t->right = avl_insert(t->right, k);
    else return t;
    return rebalance(t);                   /* at most one rotation total */
}

void inorder(const Node *t) { if (!t) return; inorder(t->left); printf("%d ", t->key); inorder(t->right); }

int main(void) {
    Node *root = NULL;
    int keys[] = {30, 10, 20, 40, 50, 60, 70};   /* exercises LL, LR, RR */
    for (int i = 0; i < 7; i++) root = avl_insert(root, keys[i]);
    printf("height = %d\n", h(root));
    inorder(root); printf("\n");                  /* 10 20 30 40 50 60 70 */
    return 0;
}

Check your understanding

Insert 10, 30, 20 into an empty AVL tree. Which case occurs and what is the result?
The path from the unbalanced node 10 is right (to 30) then left (to 20) — the RL shape. Right-rotate about 30 first, making 20 the right child of 10 with 30 below it, then left-rotate about 10. The middle value 20 ends on top, as the memory aid predicts.
How many rotations can a single AVL insertion require?
One rebalancing restores the height of the affected subtree to its pre-insertion value, so no ancestor can become unbalanced. Deletion is the operation where rotations cascade — up to O(log n) of them.
